    Cheat Sheet: OSINT (Open Source Intelligence)

    ___ _____ _____ _ _ _______ / _ \ / ____|_ _| \ | |__ __| | | | | (___ | | | \| | | | | | | |\___ \ | | | . ` | | | | |_| |____) |_| |_| |\ | | | \___/|_____/|_____|_| \_| |_|
    MODULE DE RECONNAISSANCE PASSIVE
    Hello! Bienvenue dans ma cheat sheet OSINT. C'est probablement la compétence la plus sous-estimée en cybersécurité, alors que putain c'est efficace. Voici mes techniques favorites pour trouver des infos (J'suis loin d'etre un pro)

    == 01. RECONNAISSANCE DE DOMAINE ==

    # Whois (la base de la base)
whois example.com

# DNS lookup
dig example.com +short
dig example.com ANY +noall +answer
dig MX example.com +short

# Reverse DNS lookup
dig -x 8.8.8.8 +short

# Sous-domaines (super important)
curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq -r '.[] | .name_value' | sort -u

    🧠 Pro tip: La commande crt.sh est l'une des plus efficaces pour trouver des sous-domaines via Certificate Transparency. C'est complètement passif et ça donne souvent des résultats que les scanners actifs ne trouvent pas.

    Tu peux aussi utiliser des outils comme subfinder, assetfinder ou amass pour automatiser tout ça. Personnellement, je préfère commencer par les méthodes manuelles pour bien comprendre ce qui se passe.

    == 02. RECONNAISSANCE D'ORGANISATION ==

    > Trouver des employés

    # LinkedIn (évidemment)
# Format: site:linkedin.com "at Company Name" "Current"

# Leak d'emails
curl -s "https://haveibeenpwned.com/api/v3/breachedaccount/test@example.com"

    Les employés sont d'excellentes cibles d'OSINT parce qu'ils peuvent avoir partagé accidentellement des infos sensibles. Cherche des développeurs de l'entreprise sur GitHub, Reddit et Stack Overflow. Ils postent souvent des extraits de code avec des identifiants ou des informations sur l'infrastructure.

    > Trouver des technologies utilisées

    # Wappalyzer (via navigateur ou CLI)
wappalyzer https://example.com

# DNS et technologies serveur
host -t TXT example.com
nslookup -type=txt example.com

    == 03. INFOS SUR LES INDIVIDUS ==

    # Email standard (cherche sur les réseaux sociaux)
# Format généralement: prénom.nom@entreprise.com

# Vérifier l'existence d'un email
theharvester -d example.com -b all

    🧠 Conseil d'expert: Ne sous-estime jamais les sites persos ou blogs des employés. Ils contiennent souvent des infos sur les projets internes qui peuvent révéler des détails sur l'infrastructure.

    == 04. DOCUMENTS ET MÉTADONNÉES ==

    # Recherche de documents sensibles
# Google dork: filetype:pdf site:example.com confidential

# Extraction de métadonnées d'un PDF
exiftool document.pdf

# Extraction de métadonnées d'une image
exiftool image.jpg

# Pour les documents Office
exiftool document.docx

    Les métadonnées peuvent révéler: - Noms d'utilisateurs internes - Chemins de serveurs - Versions de logiciels - Dates de création/modification

    C'est fou le nombre d'entreprises qui publient des PDFs sans nettoyer les métadonnées. Apparement on peut trouver des chemins de serveurs internes, des noms de domaine AD, et même des noms d'utilisateurs avec ce genre de techniques.

    == 05. RECHERCHES AVANCÉES AVEC DORKING ==

    > Google Dorks (les indispensables)

    # Fichiers sensibles
filetype:xls inurl:"email.xls"
filetype:txt intext:password
filetype:env
filetype:log

# Paramètres vulnérables
inurl:admin intext:username
inurl:wp-config.php
site:example.com intitle:"index of /"

    > Shodan (l'œil qui voit tout)

    # Format des requêtes
org:"Example Company"
ssl:"Example Company"
http.title:"Admin Panel"
vuln:CVE-2021-34527

    Si t'as jamais utilisé Shodan, commence tout de suite! C'est un incontournable pour trouver des systèmes vulnérables sur internet. Je l'utilise systématiquement pour repérer les services exposés d'une entreprise.

    == 06. GIT ET CODE SOURCE ==

    # Recherche de secrets dans les repos GitHub
git clone https://github.com/company/project
trufflehog --regex --entropy=False file://./project

# TruffleHog via GitHub API (requiert un token)
trufflehog github --org=CompanyName --token=GITHUB_TOKEN

    🧠 Astuce: Vérifie toujours les issues et pull requests fermées sur GitHub. Les gens y mettent souvent des extraits de code, des logs d'erreur, et parfois même des credentials, pensant que personne ne les verrait une fois la PR fermée. Grosse erreur!

    == 07. FOOTPRINTING AVANCÉ ==

    > Archives Web (Wayback Machine)

    # En CLI
waybackurls example.com | grep -v "\.css\|\.js\|\.svg" | sort -u

    C'est fou ce qu'on peut trouver sur des versions archivées de sites. Des pages d'admin qui n'existent plus, des API docs qui ont été retirées, des mentions de projets internes...

    > Suivi des modifications

    # Visualiser les changements au fil du temps
# Via l'UI de Wayback Machine ou avec:
wbd -u example.com

    == 08. KIT DE SURVIE OSINT ==

    Voici mon top 5 des outils OSINT que j'utilise systématiquement:

    1. Amass - pour l'énumération de domaines et sous-domaines
    2. TheHarvester - pour les emails et infos sur les employés
    3. Shodan - pour les appareils exposés sur internet
    4. Maltego - pour visualiser les relations entre les données
    5. TruffleHog - pour dénicher des secrets dans le code

    Et mon top 5 des sites que j'utilise constamment:

    1. crt.sh - pour les certificats SSL/TLS
    2. VirusTotal - pour l'analyse de domaines/IPs/fichiers
    3. Wayback Machine - pour l'historique des sites
    4. Hunter.io - pour trouver des emails d'entreprise
    5. Have I Been Pwned - pour vérifier les leaks d'emails
    CONSEILS ÉTHIQUES
    N'oublie pas que l'OSINT c'est de la reconnaissance passive, donc ne vas pas plus loin que ce qui est publiquement disponible. Respecte toujours: 1. La vie privée des individus (ne harcèle personne) 2. Les lois en vigueur (n'exploite pas ce que tu trouves) 3. Les limites d'accès (ne tente jamais de te connecter avec des creds trouvés) L'OSINT c'est comme être un détective digital - tu observes mais tu n'interagis pas directement avec la cible.

    Voilà, t'as maintenant tout ce qu'il te faut pour devenir un pro de l'OSINT! Si t'es patient et méthodique, tu peux découvrir des tas de choses sans même envoyer un seul paquet vers ta cible. C'est la beauté de cette discipline.

    N'hésite pas à compléter cette cheat sheet au fur et à mesure de tes découvertes. Le domaine de l'OSINT évolue constamment avec de nouvelles sources et techniques!
